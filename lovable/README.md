# Dashboard на Lovable

Переезд дашборда на Lovable. Переезжаем семь разделов — Daily Report, Weekly
Report, Monthly Review, Trends, Гант, Проекты, IT request. Первый — Гант.

Эта папка **готова к подключению**, но ещё не подключена: Lovable работает с
отдельным репозиторием, а здесь код лежит внутри `dashbord`, чтобы его можно
было посмотреть и принять до того, как появится что-то новое на GitHub.

## Два этапа, и почему именно в таком порядке

**Этап 1 — переезжает фронт, база остаётся.** Страницы живут на Lovable и
ходят в нынешний FastAPI. Он уже отдаёт `allow_origins=["*"]`, так что на
стороне сервера не меняется ничего. Данные, интеграции и ночные синки
продолжают работать как работали.

**Этап 2 — переезжает база.** Схема и функции применяются в Supabase, данные
переносятся, `VITE_DATA_SOURCE` переключается на `supabase`.

Порядок именно такой, потому что на первом этапе ничего нельзя сломать
необратимо: старый дашборд продолжает работать параллельно, и откат — это
вернуться на его адрес. Если менять хостинг и базу одним шагом, то при любой
проблеме непонятно, где она, и откатываться некуда.

## Как это подключить к Lovable

1. Завести пустой приватный репозиторий на GitHub — например
   `maico15/dashbord-lovable`.
2. Перенести туда содержимое этой папки (не саму папку — её содержимое должно
   оказаться в корне репозитория, Lovable ждёт проект в корне).
3. В Lovable: New Project → Import from GitHub → выбрать этот репозиторий.
4. В настройках проекта Lovable задать переменные окружения из `.env.example`:
   `VITE_DATA_SOURCE=rest` и `VITE_API_URL=https://dashbord-5u0i.onrender.com`.
5. После этого я работаю как сейчас: пишу код, пушу в репозиторий, Lovable
   подхватывает. Твоих действий больше не требуется.

## Как устроен слой данных

```
src/data/index.js          выбирает реализацию по VITE_DATA_SOURCE
     ├─ gantt.rest.js      нынешний FastAPI — эталон формата ответов
     └─ gantt.supabase.js  Supabase
```

Страница вызывает `ganttApi.loadBoard()`, а не `fetch`. Обе реализации обязаны
возвращать одинаковые структуры; что именно — расписано в `gantt.rest.js`,
потому что его формат сегодня работает в проде.

Переключение между ними — одна переменная окружения. Это и есть весь переезд
базы с точки зрения фронта, и поэтому откат стоит ровно столько же, сколько
переезд.

## Если надо запустить локально

```bash
cd lovable
npm install
VITE_API_URL=https://dashbord-5u0i.onrender.com npm run dev
# откроется на http://localhost:8080/team-gantt
```

## Про Tailwind

В проекте настроен Tailwind — так принято в Lovable, и так будет писаться
новый код. Перенесённый Гант им не пользуется: он оформлен через токены
`--ios-*` в `src/index.css`, ровно как на нынешнем дашборде. Одно другому не
мешает. Переписывать 4 200 строк рабочей страницы на Tailwind ради
единообразия смысла нет — риск есть, пользы нет.
